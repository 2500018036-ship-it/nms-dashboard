Based on Moby profiles commit `4b8214fc4971e06172938a1f1554ccff6647ee80`, [seccomp/default.json](https://raw.githubusercontent.com/moby/profiles/4b8214fc4971e06172938a1f1554ccff6647ee80/seccomp/default.json). The only added rule permits `clone`, `setns`, `unshare`, and `chroot` for Chromium user namespaces, following [Playwright Docker guidance](https://playwright.dev/docs/docker). `chroot` is additionally allowed because the Docker baseline otherwise filters it out when all container capabilities are dropped; the Chromium child needs it inside its own user namespace. The host kernel still requires CAP_SYS_CHROOT in the relevant namespace; no outer container capability is added. Capabilities remain fully dropped and no-new-privileges remains enabled. The current Docker profile retains the clone3 ENOSYS compatibility fallback and current glibc syscalls.
