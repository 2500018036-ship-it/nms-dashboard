# Laporan perluasan data MikroTik — 19 Oktober 2026

## 1. Penyebab dan temuan

Kode sebelumnya hanya menyediakan system/interfaces/network/vlan dengan kumpulan field tetap dan maksimal 100 baris tanpa pagination. Tidak ada tool rinci untuk trafik, klien, queue, firewall, bridge, atau sesi aktif. Command deterministik untuk memilih data router juga belum tersedia.

Akun `NMS-HomeServer` dan password yang dikonfirmasi pengguna sudah tersimpan dan cocok dengan konfigurasi aktif. Login read-only audit berhasil. Router mengembalikan grup bawaan `read`, dengan policy `local,telnet,ssh,reboot,read,test,winbox,password,web,sniff,sensitive,api,romon,rest-api,!ftp,!write,!policy`. Akun ada, tetapi belum memenuhi batas read,api yang diminta spesifikasi. Policy ini dibaca langsung; bukan asumsi bahwa nama grup read berarti least privilege. Runtime menolak pembacaan monitoring dengan `excessive_or_unverified_permissions`.

Beberapa percobaan awal API timeout dan API-SSL gagal handshake/timeout. Percobaan berikutnya berhasil login dan membaca metadata akun. Uji host sementara pertama memakai `docker --env-file` yang mempertahankan quote literal pada nilai host, sehingga gagal resolusi; diulang dengan environment yang sudah diproses Compose dari container aktif dan berhasil. `.env` maupun kredensial tidak diubah untuk mengatasi kesalahan probe tersebut.

## 2. File berubah

- `app/services/health.py`: tool `get_mikrotik_data` dengan schema ketat, batas 10 baris dan section enum.
- `app/ai/agent.py`, `prompts.py`: deteksi kebutuhan data aktual, pemetaan pertanyaan MikroTik ke section, pagination dan penjelasan UNKNOWN.
- Baru `app/telegram/mikrotik.py`, perubahan `handlers.py` dan `app/main.py`: `/mikrotik`, alias, filter, offset dan format vertikal tanpa AI.
- `app/alerts/engine.py`: configuration/permission gap tidak dianggap outage collector/layanan.
- Baru `tests/test_mikrotik.py`, perubahan `test_collectors.py` dan `test_state_telegram.py`.
- `.env.example`, `README.md`, baru `docs/MIKROTIK.md` dan laporan ini.
- `.env` server saja, tidak di-Git: opt-in read-only, detail jaringan, pengecualian API internal dan verifikasi SSL diset true. Nilai akun/password/token/model tetap sama. Runtime tetap memeriksa policy sebelum membaca data monitoring.

Compose, Dockerfile, dependensi, port, volume, network dan konfigurasi aplikasi lain tetap sama. Tidak ada query write, perubahan router, VM atau administrasi Docker dari agent.

## 3. Fitur

28 bagian: system, interfaces, traffic, addresses, routes, ipv6_addresses, ipv6_routes, dhcp_leases, dhcp_servers, dhcp_networks, dns, arp, vlan, bridge, bridge_ports, bridge_vlans, neighbors, queues, queue_tree, firewall_filter, firewall_nat, firewall_mangle, health, ppp_active, hotspot_active, wireless, wifi dan services.

Semua operasi monitoring menggunakan API `print` dan `.proplist` terpilih. Policy dibaca terlebih dahulu. Tidak ada API path/command bebas. Pagination maksimal 10 baris dari snapshot 30 detik; input filter exact divalidasi per section. Iterator berhenti setelah 501 baris dan koneksi ditutup, dengan batas 500 baris tersimpan dan penanda ketidaklengkapan. Nilai panjang dipotong dengan indikator, ukuran halaman dibatasi dan next_offset mengikuti jumlah yang benar-benar terkirim. Hasil rinci on-demand tidak disimpan ke SQLite.

Trafik menggunakan dua sampel counter sekitar satu detik; bit/detik dihitung dengan selang waktu aktual. Counter hilang/reset menghasilkan null. Pembacaan langsung `/mikrotik` tidak memanggil OpenRouter. Modul/paket opsional atau menu yang ditolak menghasilkan UNKNOWN/hasil parsial, bukan klaim router mati.

## 4. Perintah pengujian

```sh
docker build --target test -t nms-bot:test .
docker run --rm --network none nms-bot:test
docker compose config --quiet
docker compose build nms-bot
docker compose up -d --no-deps --no-build nms-bot
```

Seluruh file app/test juga diperiksa menggunakan `compile(..., 'exec')`. Probe integrasi dijalankan terpisah tanpa poller/scheduler kedua, dengan SQLite sementara dan tanpa mencetak rahasia. Audit akun hanya membaca `/user` dan `/user/group` untuk akun yang dikonfigurasi.

## 5. Hasil aktual

- **Selesai dan terverifikasi:** 97 unit/mock test lulus, suite akhir 12,204 detik, jaringan dimatikan. Meliputi seluruh catalog memakai print/proplist, proyeksi secret, filter, offset, limit, cache, batas 501 baris, output panjang, rate/counter reset, TLS, permission gate, unsupported menu, empty response, cleanup, command tanpa AI, otorisasi, format dan alert.
- **Integrasi OpenRouter terverifikasi:** model nyata `nvidia/nemotron-3.5-lightning:free` memilih `get_mikrotik_data(section=dhcp_leases)` untuk permintaan DHCP bound. Jawaban saat data belum tersedia ditahan oleh guard UNKNOWN; tidak membuat IP/status klien rekaan.
- **Login/izin RouterOS terverifikasi:** akun aktif terdeteksi pada grup bawaan read dengan izin tambahan; dua probe produksi system/interfaces mengembalikan UNKNOWN `excessive_or_unverified_permissions`.
- **Telegram API terverifikasi:** pesan uji nomor 66 terkirim ke pemilik yang diizinkan dengan enam entity HTML native, berisi status UNKNOWN yang benar dan contoh command. Ini bukan bukti input manusia untuk command baru; jalur command diuji dengan mock dan bot sebelumnya sudah dikonfirmasi membalas input manusia.
- **Terhambat konfigurasi izin:** belum ada keberhasilan mengambil CPU/RAM/interface/DHCP/VLAN aktual melalui collector yang mensyaratkan least privilege. Tidak dinyatakan sebagai keberhasilan integrasi semua 28 menu. Pengguna sedang diberi langkah Winbox untuk memindahkan akun yang sudah ada ke grup read,api.

## 6. Deployment dan rollback

Fitur telah dibangun dan service NMS direcreate sendiri. Verifikasi akhir: **healthy**, restart count **0**, monitoring dasar **9 UP / 4 UNKNOWN**. MikroTik UNKNOWN karena izin grup; bukan angka CPU atau status klien rekaan. Health dan pemeriksaan sintaks/konfigurasi lulus. Checkpoint sebelum perubahan: `/mnt/data/backups/nms-bot/pre-mikrotik-20261019T070145Z.tar.gz` mode 600 dan image `nms-bot-pre-mikrotik:20261019T070145Z`. Backup memuat source/.git/.env, tidak menyalin DB aktif. Baseline container disimpan root-only di `mikrotik-baseline-20261019T070145Z.json`. Tidak ada perubahan skema DB sehingga rollback kode tidak memerlukan restore DB.

Jika perlu rollback, gunakan prosedur README dengan checkpoint dan tag di atas; stop/recreate hanya NMS, jangan compose down atau menghapus volume. Perubahan grup RouterOS oleh administrator tidak perlu dibatalkan untuk rollback aplikasi.

## 7. Dampak layanan lain

Recreate hanya service NMS. Tidak ada restart host, Proxmox, router atau container lain, tidak ada perubahan reverse proxy maupun port aplikasi. Verifikasi akhir membandingkan ID, Running dan StartedAt **15 container lain** terhadap baseline: **tidak ada perubahan**. Perbandingan seluruh nilai credential/token/key sebelum-sesudah sama, `.env` tetap mode 600; tidak ada kredensial yang diganti.

## 8. Risiko/batas

API saat ini masih 8728 pada LAN internal, tanpa enkripsi; migrasi API-SSL dengan sertifikat/CA terverifikasi dan pembatasan sumber akun/firewall masih perlu administrator. Bot tidak mengubah hal tersebut. Raw log, password, PPP secrets, VPN private key, file backup/export, script dan DNS cache browsing tidak tersedia. Komentar/nama/metadata tetap diperlakukan sebagai data tidak tepercaya.

Nilai yang tidak dikembalikan RouterOS tidak diganti nol. Trafik dua sampel bukan monitoring bandwidth berkelanjutan. Daftar klien dan status interface bukan bukti konektivitas seluruh VLAN. Paket wireless/WiFi/sensor dapat tidak tersedia pada router ini. Untuk pertanyaan AI, field monitoring yang dipilih dikirim ke provider; gunakan command langsung bila tidak ingin data rinci diteruskan ke provider.

## 9. Berikutnya

Administrator memindahkan `NMS-HomeServer` ke grup baru `nms-monitor` dengan hanya read dan api melalui langkah di panduan, tanpa mengganti password. Tidak perlu restart bot untuk perubahan grup: verifikasi dijalankan pada snapshot baru dan error izin tidak di-cache. Setelah itu, uji live system/interfaces/DHCP/VLAN dan satu interface traffic, lalu periksa field/paket mana yang benar-benar didukung. Setelah akses stabil, lanjutkan API-SSL dan pembatasan sumber melalui perubahan router yang disetujui administrator.
